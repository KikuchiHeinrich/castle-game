## 2. 画面与信息层级

- 场景为城堡大厅：石拱窗、暮色、纹章旗、少量暖壁灯；木桌沿、深绿桌毡、象牙白牌面、暗红主按钮。
- 装饰集中在边缘。角色和环境的亮度、运动幅度低于手牌和当前行动。
- 上方看对手，中间是奖池与已出战牌，下方是当前组合、手牌和操作。
- 默认突出手牌、一个当前牌型和一个确认按钮。对手的公开牌、各出牌段张数、已押金额可读。
- 本次投入常驻；累计、上限、历史、设置按需展开。不可通过缩小文字或隐藏必要公开信息来换取简洁。

- 示意图中的角色大小与位置允许适配，但不让角色动作遮住牌面、倒计时或主按钮。

## 4. 呼吸：所有人物必做

| 项目 | 要求 |
| --- | --- |
| 帧数 | 每人 4–6 个实际绘制的动作帧 |
| 周期 | 约 2.8–4.2 秒，缓慢循环；各帧可有不同停留时长 |
| 动作 | 胸肩或衣领起伏约 1 个逻辑像素；头发、帽饰、围巾可稍滞后 |
| 稳定性 | 脚底或座位接触点不漂，头像框、名字、筹码、牌不随人物起伏 |
| 错峰 | 每个座位随机起始相位，周期可轻微不同，避免全桌同时上下动 |
| 范围 | 等待、选牌、看牌型时持续；动作播放期间由动作帧接管，结束后恢复 |

不接受把单张人物图整体缩放、上下漂浮，作为呼吸动画的全部实现。呼吸要体现身体和附属物的相对变化。

眨眼可做成独立的 2–3 帧短动作，间隔约 4–7 秒随机；不要六人一起眨眼。

## 5. 出牌：人物动作与卡牌运动合成一次演出

每人至少 6–8 帧，单次约 450–650 ms，包含收牌、挥臂、放牌、回收和回到待机。

| 时间参考 | 人物 | 卡牌 |
| --- | --- | --- |
| 0–100 ms | 收牌、轻微蓄势 | 本人选牌收拢；对手使用暗牌代理 |
| 100–200 ms | 手臂向桌面推出 | 在放牌关键帧约 150 ms，从对应出牌手位置释放 |
| 150–450 ms | 手臂跟随、回收 | 向该玩家的实际出战区飞行，随后落桌 |
| 450–650 ms | 恢复手臂、身体落位 | 牌与阴影稳定，恢复呼吸 |

- 可按实际帧调整时间，但手臂释放和牌开始飞行必须对齐。一次出牌演出原则上不超过 750 ms。
- 本人出牌要衔接已选手牌与人物放牌位置，不能出现两套重复牌；对手从对应角色的出牌手位置释放。
- 新增牌段与原出战牌段保持边界，出牌落点稳定；不能从屏幕原点飞入。
- 出牌和加牌均触发角色动作。单纯加筹码使用简短推筹码反馈，不误播出牌。
- 不能只有飞牌、人物完全不动，也不能人物挥手后隔一段时间才飞牌。
- 其他人物继续轻微呼吸，仅当前行动者挥臂。无全桌跳动、全屏震动或强粒子。

## 6. 动作触发与同步

- 成功的 `play` / `add_cards` 事件触发一次出牌；由事件序号去重。服务端拒绝的提交不播放正式出牌演出。
- 点击主按钮可立即显示按下与提交反馈，正式出牌以服务端确认的状态/事件为依据。
- 动作优先级：淘汰/离座/重置 → 本次行动 → 呼吸。呼吸不阻塞行动，也不重排其他动作。
- 同一人物连续收到动作时顺序衔接；不同人物不被呼吸动画占住全局队列。队列落后时合并或取消过时演出，优先跟随最新状态。
- 快照更新不能让所有人物从呼吸第一帧重播，不能因重建 DOM 丢失当前帧或输入焦点。
- 切换房间、离开页面、重连、事件缺口或回合已推进时，取消旧动作、飞牌和计时器，以最新快照落地。
- 页面在后台时暂停无用循环，恢复前台不补播错过的呼吸与历史动作。
- 所有倒计时使用权威截止时间，动画不延长回合。

## 7. 牌面公开规则

- 自己能看见自己的牌；对手未公开牌在蓄势、挥手、飞行、落桌全过程保持牌背。
- 每次多张出牌段只公开该段最大牌；单张出牌段不亮牌。不能因动画短暂翻面泄漏其他牌。
- 摊牌只能在相应公开事件后揭示。
- 角色动作只表达“正在出牌”等公开行为，不根据隐藏牌型播放不同稀有度或情绪，避免泄漏强弱。

## 8. 其他交互与流程

- 牌型查询位于手牌附近，默认收起；展开显示当前牌型及左右各四档，按既定顺序由弱到强。到两端不循环。
- 当前组合按“已出战牌＋新选择”计算。材料、杂牌与结算口径一致。
- 点击牌型可查结构；依据本人手牌能组成时可预选，不能自动提交或撤回已出战牌。
- 防守提供选牌、托管和确认入口；宣战、加牌、跟注、弃牌、同意摊牌各按合法动作呈现。
- 防守与弃牌后锁定相应操作；等待他人时允许查询、预选，但不自动出牌。
- 摊牌突出决定胜负的首个比较项，再派彩。防守托管与奖池分别表现，结算总演出约 2–3 秒，并服从服务端窗口。
- 已出牌回收，未出的手牌保留原位，只补缺牌。淘汰、终局、再来一局和回到大厅均需完成。

## 12. 本轮实现记录（按交接的六项）

### 12.1 牌桌流程与状态（第 1 项）

- **不限时倒计时**：服务端不限时用 `Number.MAX_SAFE_INTEGER` 作哨兵（`rules.ts` 的 `deadline()`）。`TableView.tick()` 现在对 `deadlineAt >= 8e15` 一律显示 `∞`，不再打印 `9005407178484s`。
- **离开牌桌必须卸载**：`main.ts` 在场景切走时调用 `unmountTable()`（取消 raf、`setFxHooks(null)`、取消人物动作），`mountTable()` 开头也先 `unmountTable()` 一次，避免重连/重挂时出现两条 raf 循环与残留 hooks。
- **房间页立即挂载**：切到房间场景当帧就 `mountRoom()`，不再等下一帧渲染；房间签名加入 `avatar`，形象变化也能重建座位格。
- **事件序号与快照**：判定抽到 `net/cursor.ts` 的 `planViewCursor()`（`net/socket.ts` 的 `applyView()` 调用它）。换房、序号回退（`view.eventSeq < lastEventSeq`）、回合回退（重开/新房）时把 `lastEventSeq` 重置到该快照并清队列；**正常广播**不重置——服务端 `host.commit()` 先发 `game:event` 再发 `room:state`，两者 seq 持平，正在播的动作因此不会被打断；**重连**走 `rejoin` 模式，把游标明确设成快照 `eventSeq` 并清队列，重连后第一个真实动作（seq+1）不会被判成缺口整段丢掉。服务端随快照补发的 `recentEvents` **不补播**：重连只按最新快照落地。重连回包另加会话 / 房间码校验，迟到回包不会把旧房间状态写进新局。
- **队列不再吃掉第一动作**：`anim.ts` 的队列按"入队时看到的回合"分组，新一批事件的回合与队列里残留的不同才整体作废；`render()` 不再因为回合号变化就 `resetQueue()`（原来 `round_start + deal` 紧随其后的快照会清掉刚入队的发牌演出）。
- **服务端拒绝保留选择**：`submit()` 失败时不清空选牌，并把 `toast` 文案写到 `#action-feedback`；成功才清空选择。异步返回后若已换房或换回合，不再回写旧请求的结果。
- **输入不丢焦点**：`renderDecision()` 仅在 `#bet-input` 不是活动元素时写 `value`。
- 行动入口（防守 / 不防守 / 出牌 / 加牌 / 加注 / 跟注 / 弃牌 / 同意摊牌 / 开始 / 再来一局）沿用既有 `legalActions` 判定，本轮只调整呈现与提交守卫。

### 12.2 信息层级与查询（第 2 项）

- 当前组合仍按"已出战 ＋ 新选择"计算（`decision()` 未改口径）。
- 牌型查询默认收起；展开为 9 档，当前档居中、左右各 4 档（`HAND_TYPES[rank+i-5]` 的算法原本就对，本轮补了 `aria-current`/`aria-label` 与两端空位样式 `.rank-gap`，并确认到两端不循环）。
- 对手公开信息常驻：`筹码 N 筹 · N 手`（+ 有押注时 ` · 押 N`），状态另起一行；点名字看详情（筹码 / 已押 / 手牌 / 出战 / 出牌段 / 托管 / 最近动作）。原先"筹码彻底看不见、只在手牌与押注里二选一"的问题已消除。头顶状态改走 `views/shortStatus.ts` 的短状态（去量词与空格，如 `加牌2·加注3`、`防守2·托管4`），完整 `lastAction` 句子只留在座位详情与战报记录里。
- 每段出牌加了张数角标（`.seg-count`），段与段之间保留边界；亮牌仍只亮该段最大牌。
- 摊牌面板：列出首个分出胜负的比较项（①牌型 → ②杂牌 → ③最大牌 → ④花色，第 3、4 项用共享 `evaluateSubset()` 取 `keyRank/keySuit`），并把"奖池 → 胜者""托管退还""托管入池"三件事分开写；三行只留标签与金额，"钱没进奖池""已计入上面的奖池"这类解释句已按用户要求删除。明牌时机改由权威快照决定（`roundPhase === 'settlement' && result` 才亮），亮牌节奏按服务端摊牌窗口剩余时间铺开。
- 加注的筹码飞行动画只做"从座位飞进奖池"；托管退还在座位上点亮（不飞），避免把退还画成入池。

### 12.3 响应式（第 3 项）

- **去掉模糊来源**：`table.css` 里 `.opp-card .pixel-avatar{transform:scale(.74)}` 与 `#self-seat{transform:scale(.72)}` 已删除；改用整数倍率（手机 1x、桌面 2x）。**倍率分两层**：`avatarSVG()` 内联只写默认值 `--avatar-default-scale`，`sprite.css` 里 `.pixel-avatar{--avatar-scale:var(--avatar-default-scale,2)}` 给出最终倍率，样式表（含手机媒体查询）因此可以覆盖内联值。CSS 背景尺寸、WAAPI 帧偏移（`localScale()` 读 computed 值）与 `avatarHandRect()` 锚点都用这个最终倍率，不会再出现"内联 2x 压过媒体查询 1x"。
- 手机（≤760px）对手区改为等宽网格（`repeat(auto-fit, minmax(48px,1fr))`，六人一行、320px 也不换行），名字/筹码/手牌自动换行而不裁边，状态浮到头像下沿不占高度。
- 本人座位移到**手牌行上方的左侧空档**（左 4px，手机 `bottom: calc(var(--card-h) + 168px)`——比手牌盒顶再低一点，给选中牌抬起 16px 与外圈牌旋转下探留余量；横屏矮屏降到 92px），与手牌彻底分离；名字与筹码分两行，窄屏不裁边。

### 12.4 角色与动画（第 4 项）

- `art/characters.ts`：新增 `GAP = 2` / `PITCH = 50` / `COLUMNS` / `ROWS`；出牌手位置抽成 `HAND_POS`（绘制与释放点共用同一张表，不再两处手写常量）；`motionFrameAt()` / `releaseAnchor()` 给出释放帧与其手部中心。
- 呼吸仍是逐帧绘制（胸肩 1 逻辑像素、脚底不动），并让头发/帽饰**滞后头部一帧**、斗篷按帧摆动——不是整张图上下漂。
- **呼吸相位按实例错峰**：相位 / 周期不再只看角色行，而是取"实例键"——数字键（座位号）走黄金分割分层 + 少量 FNV-1a 抖动，相邻座位至少错开约 1/3 周期；字符串键直接用散列。同一个键恒定，DOM 重挂 / 重渲染不改变相位，也不改绘制图像。实测相位 0.016–0.761 周期、周期 3.157–3.470 s（跨度 0.31 s）。牌桌的本人位与每个对手位、房间座位格都传座位号，同一个人物出现在两个座位时不再同步起伏。
- 出牌：握牌帧改为"到释放帧为止"，释放帧 `play 150ms → 第 2 帧` 时手已空；释放点 = 该帧手部中心（`x 40 · y 30.5`），与卡牌起飞对齐。
- `pixelAvatar.ts`：`avatarHandRect(element, motion)` 用**渲染后的实际比例**（`rect.width / CELL`，含祖先 transform）换算锚点；WAAPI 帧偏移与 CSS 背景尺寸都用同一倍率。
- 减弱动态不再"直接 return 无反馈"：改为 240ms 的清晰短确认（金色描边 + "出牌/防守/弃牌/胜利"文字标签）。确认原来是"样式一个定时器 + Promise 一个定时器（取消只清其中一个）"，现在合并成一份登记（`pending.ts` 的 `TimerRegistry`）+ 单一 `finish`：取消时样式与 Promise 一起收，`cancelAvatarActions()` 还会兜底清掉页面上任何 `.avatar-confirm` 残留。
- 本人出牌：提交时记录选中手牌的屏幕位置，动画先把这些牌收拢到人物手（150ms，暗牌代理），再从手部释放飞向出战区；收拢期间原手牌节点被隐藏，结束后恢复，不会出现两套重复牌。对手飞牌全程牌背。
- `anim.ts` 的 `wait()`（等待）与 `pulse()`（座位高亮）都改走 `TimerRegistry`；`resetQueue()` 清空队列、取消动画、移除飞牌节点、恢复 `[data-fx-hidden]` 手牌、清掉暂存的手牌位置与人物动作，并额外移除 `.fx-return` 座位高亮与残留的 `.fly-card` / `.flying-chip` 节点。退出场景后没有残留计时器，等待中的 Promise 会在取消时被结算（不会挂着）。
