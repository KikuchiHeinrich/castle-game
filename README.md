# 城堡 · Castle

原创扑克筹码游戏《城堡》的网页版，支持 **2~6 人在线实时对战**。像素风格卡牌 + 出牌飞入/翻面/筹码飞行动画。

> 设计稿：`~/Downloads/城堡·.txt` + 与设计者逐条确认的补充规则（见下方"规则速览"）。

## 美术素材

牌面、按钮、卡背、音效、点阵字体都取自 `Kingslayer_demo_20250322`（另一份引擎无关的
demo，只用素材、不涉及代码）。素材放在 `packages/client/public/king/`，构建时原样拷到
`dist/king/`，运行期按 `/king/...` 引用。

- 牌面用对方的 13×5 图集（单格 49×65），靠 `background-position` 定位——
  手牌 2 倍格、出战区 1 倍格，整数倍缩放所以点阵不糊
- 按钮用素材帧做 `border-image` 九宫格，图标另行切出来由 `::before` 贴回去
- 中文字体把 12.4MB 的 `namidiansong.ttf` 子集化成 85KB woff2；它是 **17px 点阵字体**，
  只有 17px / 34px 锐利，所以正文一律 17px
- 音效优先播真实素材，素材未就绪时回落到程序化合成，任何情况下都有反馈

素材切分与字体子集化的步骤见 [`scripts/README-art.md`](scripts/README-art.md)；
按钮切分脚本是 `scripts/slice-art.py`。

## 规则速览

- 52 张牌无王，A 可作高也可作低；花色序 黑桃>梅花>红桃>方片
- 每人初始 100 筹码，每回合底注 1，筹码归零淘汰，最后存活者胜
- **备战**：打出去的牌回牌堆，未使用的手牌继承到下一回合，只补足到 6 张（建房时可调筹码倍数：上限 = 牌数 × 倍数）
- **手牌三重身份**：出战区的牌既是牌型材料，又是押注上限（`累计押注 ≤ 出战区牌数`），张数公开、只亮最大牌 → bluff 空间
- **防守**：回合开始前可宣布防守：用 N 张手牌防守 = 本回合总投入 N 筹码（含底注，底注之外的差额为托管），宣布后本回合锁定；牌型全场最大 → 收回托管，否则托管进奖池；奖池永远由非防守者争夺
- **摊牌**：各取"最大可组成牌形"比较：① 牌型排名 → ② 杂牌少者胜（掺水）→ ③ 牌型内最大牌 → ④ 花色
- **22 种牌型**（小→大）：散兵/单剑/浪花/术士/双剑/洪水/学者/骑士/领主/博士/海啸/龙/大剑/公爵/魔导/灾难/贤者/正义/皇帝/龙王/使徒/暴君（游戏内点"牌型表"随时查看）

## 快速开始

```bash
npm install
npm run dev        # 同时启动服务端(:3000)与前端(:5173)，浏览器开 http://localhost:5173
```

自测多人：**开多个浏览器标签页**（sessionStorage 保证每个标签页独立身份），或房主点"+ 电脑玩家"加机器人。

## 生产构建与运行

```bash
npm run build      # esbuild 打包服务端 + vite 打包客户端
npm start          # 单进程托管 WebSocket + 静态前端（PORT 环境变量，默认 3000）
npx tsx scripts/smoke.ts 3210   # 冒烟脚本（先 PORT=3210 npm start）
```

## 测试

```bash
npm test           # 65 个用例：22 牌型判定/掺水/永不分序 fuzz/规则状态机整局/防作弊视图/服务器集成
```

## 部署（Railway）

1. 推到 GitHub，Railway New Project → Deploy from repo
2. Nixpacks 会按 `railway.toml`：`npm ci && npm run build` → `npm start`，健康检查 `/healthz`
3. 无需额外环境变量（`PORT` 平台注入）；前端与 WebSocket 同源，无 CORS 配置

其他平台（Render/Fly/VPS）同理：Node ≥ 20，`build` + `start` 两条命令即可。

## 架构

```
packages/
├── shared/   纯函数规则引擎（前后端共用，零依赖）
│   ├── evaluator.ts   22 牌型识别 + 比较元组 + bestHand（≤63 子集枚举）
│   ├── rules.ts       状态机 applyAction/tick（超时自动动作、虚拟时钟可测）
│   ├── legal.ts       合法操作（服务端校验与前端按钮共用）
│   └── view.ts        buildPlayerView 防作弊过滤（他人手牌/牌堆/种子绝不外发）
├── server/   Express 5 + Socket.IO：房间/会话(token)/超时调度/机器人/TTL 清扫
└── client/   Vite + TS（无框架）：DOM 卡牌 + 事件驱动动画（飞卡/翻面/筹码/横幅）
```

关键设计：

- **服务端权威**：每个动作先过 `legalActions` 校验；集成测试断言推送流中不含他人私有手牌
- **状态兜底，事件只负责好看**：`room:state` 快照即时覆盖 store；`game:event` 只驱动动画，事件序号跳变（重连/丢包）时丢弃动画直接同步到快照
- **座位号稳定**：大厅离座只置空座位不重排，重连 token 按座位索引不会串座
- **超时托管**：防守窗口 12s / 宣战 30s / 轮转 30s 自动最小行动或补齐押注，全桌 90s 无动作自动同意，断线玩家不踢出场由托管代打

## 已知限制

- 单实例内存房间：进程重启对局即失（派对游戏可接受）；扩容需 Redis adapter + sticky session
- 引擎内四个实现默认值（弃牌者不计入 maxBet / A 低顺最大牌取顺子顶 / 防守结算细则 / 全员防守作废回合）各隔离在单点，改规则成本低
